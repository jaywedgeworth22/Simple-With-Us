iOS usage dashboard

One screen for every AI subscription you pay for.

Usage Client Monitor rolls up your API spend across OpenAI, Anthropic, Google, and a dozen other providers into a single iOS dashboard. Per-day, per-week, per-month; per-model, per-team, per-account. The server is yours -- self-host free, point the app at it, and your usage syncs across every device.

What's inside

  • Multi-provider rollup. One rollup screen for every connected provider, broken out by day, week, and month, with a sparkline at the top.
  • Per-model breakdowns. Drill from a provider into a model; see which models dominate your spend and which are barely ticking.
  • Cap detection. Set a per-provider or per-model threshold. The app warns you at 80% and 100%, both in-app and via local notification.
  • Self-hosted server. Point the app at your own server (free, source available) for cross-device sync. Or run the iOS app alone; it works either way.
  • CSV export. Per-provider, per-account, per-date-range. Export once, archive forever.

How it works

Usage Client Monitor reads usage from each provider's usage endpoint using API keys you supply in-app. Keys live in the iOS keychain by default; if you run the self-hosted server, you can opt to share them across your devices. The app never proxies your traffic -- it talks to each provider directly.

  1. Add a provider and paste the API key. The app pulls usage history on first connect.
  2. Optionally point the app at your self-hosted server URL in Settings for cross-device sync.
  3. Set caps in the Cap screen. The app warns when you approach the line.

What it doesn't do

  • Subscription management. The app reads usage; it does not pause, downgrade, or cancel your provider plan.
  • Billing reconciliation. Usage endpoints report API spend, not invoice charges. Treat the two as separate ledgers.
  • Real-time minute-by-minute. Pulls refresh every few minutes; not a high-frequency telemetry stream.

Privacy

Usage Client Monitor stores API keys in the iOS keychain by default. The app reads each provider's usage endpoint directly; no Simple With Us relay. Crash reports are opt-in and scrubbed of identifiers. Full notice at /privacy.

Need help?

The most common issue is the self-hosted server URL being reachable from the iPhone but not the Mac. The support page covers the four checks that catch 90% of sync issues; if those don't help, write to feedback@simplewithus.com with your server URL and provider list.
