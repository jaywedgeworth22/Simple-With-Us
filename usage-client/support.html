Support

Provider keys, self-host server, and known-issue reference. If the four checks below don't fix it, send the output to feedback@simplewithus.com and we'll come back the same day.

The four checks that catch 90% of sync issues

  1. Provider key still valid. Most "the app stopped updating" reports trace back to an expired or rotated API key. Re-issue the key at the provider, paste it into the app, and pull-to-refresh on the rollup screen.
  2. Self-host server reachable. From the iPhone, open the server URL in Safari. If Safari can't reach it, neither can the app. Check your LAN, your tunnel, and your DNS.
  3. Server version compatibility. Older server builds don't speak the current sync protocol. Check the release notes for the server and bump if you're behind.
  4. iOS keychain intact. If you wiped the device or restored from an old backup, the keychain entry for the provider key may be gone. Re-add it in the Providers screen.

Crash log or "Application keeps closing"

If Usage Client Monitor crashes immediately on launch or after a specific screen, pull a Console log from the Mac (Console.app > iPhone > Usage Client Monitor) and send the last ~200 lines to feedback@simplewithus.com. If you can repro, note the exact steps and the iOS version (Settings > General > About).

Usage numbers don't match the provider dashboard

Usage endpoints report API spend; provider dashboards report invoiced charges. Discounts, credits, refunds, and proration can show up on the invoice but not on the usage endpoint. Treat the two as separate ledgers; reconcile monthly, not daily.

Sending logs to support

The app's Settings screen has a "Send Logs" action (under Diagnostics). It bundles the last few minutes into a single zip, scrubbed of your API keys, and opens a prefilled email to feedback@simplewithus.com. Attach the zip; we respond usually within a business day.

Contact

feedback@simplewithus.com -- open a thread, don't worry about templates. Note your iOS version and the providers you've connected.
