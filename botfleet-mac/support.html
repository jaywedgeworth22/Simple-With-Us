BotFleet for Mac

Support

Menu-bar launch, permissions, and known-issue reference. If the four checks below don't fix it, send the output to feedback@simplewithus.com and we'll come back the same day.

The four checks that catch 90% of companion-launch failures

  1. Mac: is the companion running? Open Terminal, paste launchctl list | grep botfleet. You should see a row for the companion. If not: launchctl load -w ~/Library/LaunchAgents/com.simplewithus.botfleet.companion.plist.
  2. Mac: same network as the orchestrator? The companion and the orchestrator must be reachable to each other on localhost or a local subnet. If the orchestrator is on a different host, set ORCHESTRATOR_HOST in the companion's plist.
  3. macOS: Notifications permission. Open System Settings > Notifications > BotFleet. If notifications are off, the shared-notifications feature stays silent. Toggle on and pick "Alerts".
  4. macOS: persistent settings. If the companion has stopped connecting after a Mac reboot, open the app once from Applications to re-register the menu-bar item; the LaunchAgent alone does not bring back a hidden menu-bar entry.

Crash log or "Application keeps closing"

If the companion disappears from the menu bar or crashes on launch, open Console.app and filter by process BotFleetCompanion. Send the last ~200 lines to feedback@simplewithus.com. If you can also repro the crash, note the steps.

Menu bar icon never appears

This is almost always a LaunchAgent that didn't load, or a hidden menu-bar entry. Run launchctl list | grep botfleet to confirm the agent is registered; if it isn't, re-install via the bundled installer. If it is registered but the icon is hidden, open the app once from Applications to reveal it.

Sending logs to support

The app's Help menu has a "Send Logs" action. It bundles the last few minutes into a single zip, scrubbed of your local token, and opens a prefilled email to feedback@simplewithus.com. Attach the zip; we respond usually within a business day.

Contact
